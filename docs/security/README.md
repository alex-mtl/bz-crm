# Безопасность

> Требования: ТЗ §15–17, §30, §49–50, §52; ФО §3.1, §6.3.4, §6.16.

## Что есть на конец Фазы 0

| Мера | Реализация |
|---|---|
| CSRF | стандартный middleware Laravel/Filament |
| Хеширование паролей | bcrypt (`BCRYPT_ROUNDS=12`) |
| Сессии | серверные, в Redis |
| Доступ в админ-панель | только аутентифицированные пользователи с подтверждённым email — **временно**, до ролей в фазе 1 |
| `/health` | без деталей ошибок в ответе, rate limit 60/мин |
| Заголовки | `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`, скрыт `X-Powered-By` (nginx) |
| Прямой доступ к `.php` кроме `index.php` и к dot-файлам | запрещён (nginx) |
| Секреты | только `.env`, файл в `.gitignore` |

## Обязательно в следующих фазах

- Центральный `AuthorizationService` и матрица тестов доступа ТЗ §52 — фазы 1–2.
- TOTP 2FA, журнал входов, принудительное завершение сессий, защита от перебора — фаза 1.
- Журнал событий ядра (Д-4, ADR-006) — первый блок фазы 1: append-only, запись в одной транзакции с действием, маскировка секретов, просмотр по отдельной привилегии.
- Логирование доступа к конфиденциальным слоям, запрет массового экспорта этих слоёв — фаза 2 (через журнал фазы 1).
- Шифрование секретов интеграций, в UI — только факт наличия — фазы 1 (OAuth-провайдеры) и 10 (каналы).
- Проверка подписи вебхуков и идемпотентность — фаза 10.
- Content-Security-Policy — при появлении пользовательского интерфейса вне Filament.

## Правила для всего кода

- Скрытие кнопки не является проверкой прав (ТЗ §15).
- Чувствительные данные не пишутся в логи, не уходят в поисковый индекс, в уведомления и стороннему AI-провайдеру по умолчанию (ТЗ §50).
- Секреты не выводятся в логах, API-ответах, отладочных страницах, аудите, таблицах Filament (ТЗ §49).
