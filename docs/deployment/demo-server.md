# Демо-стенд на сервере

Стенд показывает платформу на **вымышленном демо-мире** (Д-2) с быстрым входом под персонажами (Д-5). Это не продакшен: реальные данные сюда не вносить.

| | |
|---|---|
| Сервер | AWS EC2 `35.88.203.152` (Ubuntu 26.04, ARM64, 2 ядра, 8 ГБ), SSH: `ssh aws-bz` |
| Адреса | `https://ec2-35-88-203-152.us-west-2.compute.amazonaws.com` и `http://35.88.203.152` |
| Каталог | `/opt/bz-crm` — код из git (без истории), `.env` стенда |
| Защита | нет: по решению заказчика стенд открыт всем, кто знает адрес; быстрый вход доступен любому |

## Как устроено

`deploy/demo/compose.yml` — те же контейнеры, что локально (`app`, `queue`, `scheduler`, `reverb`, `nginx`, `mysql`, `redis`), плюс **Caddy** — единственный, кто открыт наружу (порты 80 и 443):

- выпускает и продлевает TLS-сертификат для имени Amazon;
- по IP отвечает по обычному HTTP — это работает при любой судьбе сертификатов;
- `/app/*` (WebSocket мессенджера) отдаёт в Reverb, всё остальное — в nginx.

MySQL, Redis, nginx и Reverb наружу не открыты. Приложение доверяет заголовкам прокси (`TRUSTED_PROXIES=*`) — иначе на HTTPS-странице оно строило бы http-ссылки на стили и скрипты.

Отличия от локальной среды: `APP_ENV=demo`, `APP_DEBUG=false`, письма пишутся в лог (`MAIL_MAILER=log` — адресов демо-мира не существует), фронтенд собран (`npm run build`), а не отдаётся dev-сервером, процессы PHP работают от `www-data`. Антивирус выключен (Д-28), Playwright и ClamAV на стенде не ставятся.

**Что работает только по HTTPS.** Приложение агитатора без сети (service worker) и передача местоположения требуют защищённого адреса: по `http://35.88.203.152` они не работают, по имени Amazon с сертификатом — работают.

## Обновить стенд

С рабочего ПК, из каталога проекта:

```bash
git archive --format=tar HEAD | ssh aws-bz 'tar -x -C /opt/bz-crm'
```

```bash
ssh aws-bz '/opt/bz-crm/deploy/demo/deploy.sh'
```

Первая команда переносит закоммиченный код (без `.env`, без истории; удалённые из git файлы на сервере остаются). Вторая ставит зависимости, собирает фронтенд и применяет миграции; данные стенда сохраняются. `deploy.sh --fresh` — то же, но демо-мир строится заново (около минуты; всё, что сделано на стенде руками, пропадает).

## Обслуживание

```bash
ssh aws-bz
cd /opt/bz-crm
./deploy/demo/dc ps                       # состояние контейнеров
./deploy/demo/dc logs -f --tail=100 app   # журнал PHP; caddy — сертификаты
./deploy/demo/dc exec -u www-data app php artisan …
```

`.env` стенда создан один раз скриптом `deploy/demo/init-env.sh` со случайными секретами (ключ приложения, пароли БД, ключи Reverb, общий пароль персонажей) и больше не перезаписывается. Читать его могут только приложение и пользователь `ubuntu`. Общий пароль демо-персонажей — `DEMO_USER_PASSWORD` в этом файле; для быстрого входа он не нужен.

Контейнеры перезапускаются сами после перезагрузки сервера (`restart: unless-stopped`, Docker включён в автозапуск).
