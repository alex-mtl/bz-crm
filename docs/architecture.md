# Архитектура BZ-CRM-Social

> Архитектурная память проекта (ТЗ §78). Первоисточники: [`functional-spec.md`](functional-spec.md) — ЧТО делает система, [`technical-architecture-v1.md`](technical-architecture-v1.md) — КАК она реализуется, [`requirements-addendum.md`](requirements-addendum.md) — решения заказчика, принятые позже (Д-1 «регион = территория», Д-2 «демо-мир», Д-3 «территориальный доступ», Д-4 «журнал событий в ядре», Д-5 «быстрый вход демо-персонажей»). При конфликте действует порядок из ТЗ §0; дополнения с более поздней датой имеют приоритет над исходными документами.

## 1. Суть

Внутренняя платформа организации, объединяющая CRM, мини-ERP, корпоративную соцсеть и мессенджер (ФО §0) с многослойной системой доступа, которая пронизывает все модули с первого дня.

Архитектура — **Laravel modular monolith** ([ADR-001](decisions/ADR-001-laravel-modular-monolith.md)).

## 3. Слои и каталоги

```
app/
  Domain/<Module>/        бизнес-модули (21): модели, Actions, Services, Policies, Events, Queries…
  Infrastructure/<Name>/  адаптеры внешних систем и инфраструктуры (Health, ExternalAuth, Chatwoot, Search…)
  Support/                общий код без знания о домене (Actions, Data, Enums, Exceptions, Helpers)
  Filament/               слой представления: панели, ресурсы, страницы — без бизнес-логики
  Http/                   контроллеры, middleware, form requests, API resources
  Providers/
```

Поток вызовов (ТЗ §8):

```
Filament / Livewire / Controller / Job / Command
        ↓
Action / Service               ← бизнес-логика
        ↓
Access\AuthorizationService    ← единая проверка прав (ТЗ §15)
        ↓
Model / Query-класс
```

Правила границ проверяются архитектурными тестами (`tests/Architecture`). Граф зависимостей модулей — [`modules/dependency-graph.md`](modules/dependency-graph.md), логическая модель — [`modules/logical-model.md`](modules/logical-model.md).

Состояние на конец фазы 6:

| Geo (ядро) | Дерево `Territory` с материализованным путём, уровни — справочник; идемпотентный импорт `geo:import-territories` (все окружения); контуры и точки только через `GeoService`; ответственные за территорию |
| Organization | Дерево `OrgUnit` с руководителями и 0..N территориями; членство ровно в одном подразделении с историей переводов; непосредственный начальник (Д-11) с правилами по умолчанию; `OrgStructure` (цепочка начальников, подчинённые, коллеги) |
| Profiles | Открытый профиль и контакты с видимостью «всем / региону / коллегам / руководству» (Д-12, Д-13); служебный слой, HR-характеристики, заметки психолога и СБ, заметки «360» (Д-14) — отдельные зашифрованные сущности, каждый просмотр — в журнале |
| Projects | Проекты с этапами и без, зависимости этапов, шаблоны, участники, бюджет и ресурсы план/факт, health-статус, дашборд, Гантт и таймлайн |
| Tasks | Задачи с исполнителями / наблюдателями / предметом (Д-15), подзадачи до 4 уровней, чек-листы, зависимости, повтор, учёт времени, массовые операции; статусы, приоритеты и типы — справочники, переходы — данные + правила кода; `TaskStatusChanged`; эскалация `tasks:escalate`; подсказка о переназначении при деактивации; список, канбан, календарь |

| Files (часть) | Порт `AttachmentScanner` и `FileGate`: проверка загружаемых файлов постов, мероприятий и сообщений; адаптеры ClamAV и «без проверки». Документы и версии — позже |

| CRM | Связи между людьми; лента взаимодействий (звонки, встречи, лиды, обращения, задачи, статусы — каждый источник под своим правом); очередь возможных дублей и слияние без потери истории; настраиваемые воронки и лиды с историей перемещений, причинами потери, заморозкой и автовозвратом (`crm:unfreeze-leads`), доска воронки; обращения с жизненным циклом, ответственным, сроком и задачами; сегменты и сохранённые фильтры; импорт людей CSV/XLSX (проверка = предпросмотр и dry-run, отчёт об ошибках, «всё или ничего», откат) и экспорт людей, лидов, обращений по явному праву |

| Notifications | Категории уведомлений от модулей; настройки человека с умолчаниями по ролям; каналы «в системе» и email (push отложен, Д-23); одна реализация маршрутизации для всех уведомлений (`RoutesByPreference`), письмо строится из той же нагрузки на языке получателя; центр уведомлений; объявления по области и критичные уведомления с подтверждением прочтения; ежедневный и еженедельный дайджесты (`notifications:digest`); опустошение уведомлений о предмете, к которому пропал доступ (`Retraction`) |
| CustomObjects | Только пользовательские поля карточки человека (текст, число, дата, да/нет, список); конструктор типов объектов — фаза 9 |

Real-time (с фазы 6): по WebSocket идёт только сигнал «что-то изменилось», содержимое страница перечитывает через сервер; без Reverb работает опрос раз в 20 секунд. Файлы сообщений — на закрытом диске `local`, отдаются тем, кто читает чат, и только после антивирусной проверки.

Уведомления всех модулей с фазы 5 идут по настройкам получателя: в системе (колокольчик Filament и центр уведомлений) и по email; push отложен (Д-23). Файлы постов — на закрытом диске `local`, отдаются только через приложение тем, кто видит пост. Первые эндпоинты API v1 (`/api/v1/feed`, `/api/v1/posts/{id}`) работают на сеансе панели и тех же доменных сервисах ([ADR-010](decisions/ADR-010-social-visibility-groups-api.md), [`api/README.md`](api/README.md)). Файлы импорта и экспорта лежат на закрытом диске `local` (`storage/app/private`); чтение и запись CSV/XLSX — только через `App\Support\Spreadsheet\Spreadsheet`.

Страницы вне панели (Blade, `routes/web.php`): статус учётной записи для заявителей (`/account`), подтверждение email, принятие приглашения, OAuth и второй фактор после OAuth, переключение языка, быстрый демо-вход.

Модуль Audit — **журнал событий ядра** (Д-4, [ADR-006](decisions/ADR-006-event-journal.md)). Реализуется первым в фазе 1. Все модули пишут в него через единое API в той же транзакции, что и действие. Это бизнес-журнал «кто, что, когда, над чем», отдельный от технических логов приложения (раздел 6).

Территориальный доступ (Д-3): подразделение и сотрудник привязываются к 0..N территориям; действующий доступ сотрудника = территории его подразделения ∪ выданные ему дополнительные территории.

Модуль Geo разделён на две части (Д-1): ядро `Geo\Territory` — дерево территорий, на котором строятся области прав «регион» и региональная видимость (реализовано в фазе 2); полевая часть — дома, квартиры, визиты, геозоны (фаза 7).

## 4a. Демо-мир (Д-2)

Параллельно с разработкой платформа наполняется одним связным вымышленным миром — территории, подразделения, персонажи и их деятельность. Он показывает все возможности и все ограничения системы. Данные создаются через доменные Actions, запуск в `production` запрещён. Сценарные тесты `tests/Scenarios` проверяют на нём утверждения «персонаж X может / не может Y». Описание персонажей и сценариев демонстрации — [`demo/README.md`](demo/README.md). Сценарные тесты работают в отдельной базе `bz_crm_scenarios`: мир загружается один раз на прогон, каждый тест выполняется в транзакции с откатом. Быстрый вход под персонажами (Д-5) — только в окружениях из `config/demo.php`; в `production` не регистрируется.

## 5. Среда выполнения

Локально — Docker Compose ([ADR-004](decisions/ADR-004-local-docker-environment.md), инструкция — [`deployment/local-development.md`](deployment/local-development.md)):

```
browser ──▶ nginx :8100 ──▶ app (php-fpm) ──▶ mysql
                               │   └────────▶ redis ◀── queue (queue:work)
                               │                  ◀── scheduler (schedule:work)
                               ├──▶ mailpit (SMTP; UI :8126)
                               ├──▶ reverb :8080 (публикация событий)
                               └──▶ clamav :3310 (необязательный, профиль antivirus)
browser ──▶ reverb :8180 (WebSocket)
browser ──▶ node/vite :5174 (dev-ассеты, HMR)
```

Production-топология ещё не определена (зависит от ответа на вопрос 1 из ФО §12 о хостинге).

## 6. Наблюдаемость (ТЗ §57)

- `GET /up` — liveness-проверка Laravel.
- `GET /health` — JSON с состоянием БД, Redis, кэша, файлового хранилища; `200` если всё в порядке, `503` при деградации. Детали ошибок в ответ не попадают, только в лог. Ограничен 60 запросами в минуту.
- Страница «Состояние системы» в админ-панели — те же проверки плюс число упавших задач очереди.
- Логи — JSON (`storage/logs/app.json.log`, ротация 14 дней), канал `json` в `config/logging.php`.

## 7. Локализация (ТЗ §48)

Языки: `ro` (по умолчанию), `ru`, `en`; `fallback` — `en`. Системные строки только через файлы `lang/`. Стандартные переводы Laravel — пакет `laravel-lang`, переводы Filament — встроенные.

## 8. Качество (ТЗ §51, §61, §77)

```
docker compose exec app composer check          # всё сразу: Pint + Larastan + Pest
docker compose exec app php artisan test        # Pest: Unit, Feature, Scenarios, Architecture
docker compose exec app vendor/bin/pint --test  # стиль
docker compose exec app vendor/bin/phpstan analyse --memory-limit=1G
```

CI — `.github/workflows/ci.yml`: те же три проверки на MySQL 8.4 + Redis, плюс сборка ассетов.
