# ADR-010. Соцсеть и группы: видимость постов, модерация, API v1

**Статус:** принято (фаза 4, 2026-10-01)
**Контекст:** ФО §6.4, §6.5; ТЗ §18, §19, §52, §68; Д-1, Д-3, Д-17; каталог прав §6.

## 1. Видимость поста — один SQL-запрос, от которого начинается всё

`Social\PostVisibility::visibleTo(User)` возвращает запрос по каноническим постам, уже ограниченный тем, что видит пользователь. Лента (`Feed`), её режимы и фильтры, поиск, API, счётчики, уведомления (`among()`), вложения и репосты начинают с него и могут только сужать. Отдельной «проверки для API» или «проверки для поиска» нет — поэтому расхождение между экранами невозможно по построению.

| Видимость | Кто видит |
|---|---|
| публичный | все с `posts.read` — включая кандидатов и волонтёров (Д-25) |
| региональный | не для кандидата (он видит «только явно открытое»); для остальных — территории поста пересекаются с действующим территориальным доступом читателя (Д-3) **в обе стороны**: пост на район видят его сектора, пост на сектор видит район и выше |
| групповой | участники хотя бы одной группы поста |
| целевой | люди из списка и носители перечисленных ролей (действующих, включая делегированные) |
| приватный | только автор |

Автор всегда видит свои посты. Скрытый модератором пост видит только автор (с причиной). Суперадмин **не** получает чужие приватные посты и посты секретных групп: видимость поста — не область роли. Доступ «по необходимости» — имперсонация с причиной и журналом (Д-19).

Лента — проекция, копий постов нет (ТЗ §18). Комментарии, реакции, голоса в опросе, жалобы собственной видимости не имеют: кто не видит пост, тот под ним ничего не читает и не делает.

## 2. Кто куда может публиковать

Автор выбирает аудиторию, но только ту, на которую у него есть право (каталог §6):

- приватно, в **свои** группы, списку людей, которых он видит (`people.read`), — `posts.create`;
- на территорию — `posts.publish.region`: у сотрудника «Т — только свои территории» (территориальный доступ Д-3; территория **выше** своей недоступна), у руководителя организации — любая;
- всей организации и целой роли («всем руководителям») — `posts.publish.global`.

Аудиторию позже меняет автор или модератор поста — на ту, куда меняющий сам вправе публиковать; закрепления при этом снимаются.

## 3. Модерация

Область модератора определяется **автором** контента: для `Post` и `Comment` зарегистрирован `PersonLocator` по `author_person_id`. Региональный модератор и руководитель подразделения достают контент людей своей области; модератор группы (владелец, админ, модератор) — контент этой группы, через отношение `RELATION_GRANT` без системной роли. Автор поста может скрывать комментарии под ним (ФО §6.4.3).

Мут — запись `moderation_actions` со сроком. Действует по часам (`expires_at > now()`), а не по фоновой задаче: планировщик `social:tick` лишь закрывает истёкшие муты записью в журнале и публикует отложенные посты. Отложенный пост замьюченного автора ждёт конца мута. Мут запрещает публиковать и комментировать; читать, ставить реакции и писать черновики можно.

Каждое действие модератора — запись в журнале; просмотр истории правок чужого поста — тоже.

## 4. Группы

- Открытая — вступает любой с `groups.join`; закрытая — заявка или приглашение; секретная — существует только для участников (`GroupAccess::visible()`): в списках, поиске, счётчиках, выборе аудитории, API. До вступления секретная группа видна приглашённому только как приглашение.
- Управление и модерация — по роли **внутри группы**, а не по системной роли; системное `groups.manage` есть только у суперадмина и действует на видимые ему группы.
- Привязка группы к подразделению, территории, проекту — отдельное право `groups.link.manage` в области держателя.
- Массовое приглашение — по фильтру людей, пересечённому с областью права `groups.invite.bulk`; только активные учётные записи; не больше 1000 за раз.
- Ссылка-приглашение: в базе хранится только хеш токена, токен показывается один раз; срок и число использований; переход по ссылке ничего не меняет — человек подтверждает вступление.
- Чат группы — минимальная модель обсуждений из фазы 2 (`Messaging\Discussions`), состав чата синхронизируется с составом группы. Полноценный мессенджер — фаза 6.
- «Файлы группы» — вложения постов группы, видимые читателю. Отдельное файловое хранилище группы появится вместе с модулем Files.

## 5. Вложения

Файлы постов лежат на закрытом диске `local` (`social/posts/{id}/…`) и отдаются только через `SocialAttachmentController` → `ManagePosts::attachmentPath()` тем, кто видит пост. Публичных ссылок нет (ТЗ §68). Антивирусная проверка — вопрос T2, фаза 6.

## 6. API v1

`GET /api/v1/feed`, `GET /api/v1/posts/{id}` — первые эндпоинты API. Решения:

- Аутентификация — **сеанс панели** (группа `web`, `auth`, троттлинг 120/мин). Токены для внешних клиентов и мобильного приложения — в фазе интеграций; тогда меняется только способ аутентификации, контроллеры и правила остаются.
- Контроллер не содержит правил: те же `Feed`, `PostVisibility`, `PostCards`, что и экран.
- Невидимый пост отвечает **404**, а не 403: существование не раскрывается.
- Формат: `{data, meta}`; ошибки — JSON (`shouldRenderJsonWhen('api/*')`).
