# ADR-008: Области действия, территориальный доступ и связи

- **Статус:** принято (2026-10-01, фаза 2)
- **Источник:** ФО §3.5, §6.2, §8; ТЗ §14–15, §52; Д-3, Д-11…Д-13, Д-17; развивает [ADR-003](ADR-003-authorization-architecture.md)

## Решение

Проверка `AuthorizationService::can(user, code, subject)`:

```
deny этого кода в любой действующей роли → нет
иначе есть грант кода, для которого
    область назначения роли покрывает объект            (данные «по области»)
  или связь пользователя с объектом допускается слоем данных гранта («свои», «по связи»)
иначе есть связь, дающая код сама по себе (например, непосредственный начальник)
и объектные правила кода выполняются
и жёсткие ограничения не запрещают
```

### Назначение роли

`user_roles` хранит область назначения:

| `scope_type` | Что покрывает |
|---|---|
| `null` | вся организация |
| `org_unit` + id | подразделение и все дочерние |
| `territory` + id | территория и всё её поддерево |
| `own_unit` | своё подразделение с дочерними — «едет» за сотрудником при переводе |
| `own_territories` | действующий территориальный доступ сотрудника (Д-3) |

- **Две оси независимы.** Грант по подразделению не покрывает территорию и наоборот.
- **Слой данных права роли** (`role_permissions.data_scope`): `null` — решает область назначения; `own` — только свои объекты; `related` — свои и связанные. Так в стартовом наборе сотрудник читает только задачи, где он постановщик, исполнитель или наблюдатель.
- **Наследование ролей** (`roles.inherits_role_id`): права родительской роли действуют в области того же назначения. Поэтому стартовые роли друг от друга не наследуются. Руководители и служебные роли получают роль «Сотрудник» отдельным назначением на всю организацию. Иначе руководитель филиала видел бы открытые профили уже, чем рядовой сотрудник.
- **Делегирование** — назначение с `kind = delegation`: срок и причина обязательны.
- **Автоотзыв по сроку.** Истёкшее назначение перестаёт действовать сразу. Планировщик (`access:expire`, каждые 15 минут) записывает автоотзыв в журнал.
- **`deny`** из любой действующей роли запрещает код везде.

### Где живёт объект — локаторы

Модуль регистрирует для класса `ScopeLocator`: пути подразделений и территорий объекта, а также те же условия для SQL. Пути материализованные (`/1/7/42/`), поэтому «входит в поддерево» — это сравнение префикса. Оно одинаково в PHP и в SQL, так что `scopeQuery` фильтрует списки, поиск, экспорт и счётчики в базе.

- **Человек, пользователь** — подразделение человека и территории этого подразделения. Прямые назначения территорий положение человека не меняют (Д-13, «регион владельца»).
- **Подразделение, территория** — сам узел. Несохранённый узел нигде не находится, его покрывает только область «вся организация»: так проверяется создание корня.
- **Проекты, задачи** — своё подразделение и своя территория. Если территория не задана — территории подразделения.

### Связи

`addRelation(code, kind, check, query)`. `kind`:
- `own` и `related` — связи, которые использует слой данных гранта;
- `grant` — связь сама даёт код без роли. Например, непосредственный начальник видит служебный слой подчинённого (ФО §8, Д-11), а подсказку о втором аккаунте видит начальник найденного сотрудника (Д-10).

### Территориальный доступ сотрудника (Д-3)

- Действующий доступ = территории подразделения ∪ прямые назначения в силе. Он вычисляется при каждом запросе, а не копируется, поэтому перевод и перепривязка подразделения действуют сразу.
- **Кто выдаёт территорию:** непосредственный начальник (по связи); кто-то выше в цепочке, если у него есть `access.territories.grant`; или держатель этого права с областью, которая покрывает сотрудника.
- **Что можно выдать:** только в пределах собственного действующего доступа или области права. Причина обязательна, срок — по желанию. Отказ записывается в журнал.

### «Не больше, чем у себя» (Д-17)

Роль можно назначить, если у назначающего есть каждый её код. Для кодов со слоем данных «по области» нужно ещё, чтобы грант назначающего покрывал область нового назначения. Область «вся организация» покрывается только правом на всю организацию.

## Последствия

- Сервисы авторизации, оргструктуры и территориального доступа — `scoped` (на запрос или задачу очереди): кэш прав не переживает запрос.
- Новый модуль подключается регистрацией локатора и связей в своём провайдере. Код сервиса прав при этом не меняется (ФО §3.5).
