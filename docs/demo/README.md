# Демо-мир BZ-CRM-Social

Единый вымышленный мир (Д-2), на котором видно, что система умеет и что она запрещает. Растёт от фазы к фазе теми же персонажами. Все люди вымышленные; совпадения случайны.

## Как поднять

```bash
docker compose exec app php artisan migrate:fresh --seed
```

- Окружения: `local`, `demo`, `testing` (`config/demo.php`). В `production` сидер и быстрый вход не работают — это проверяет [`DemoSeederGuardTest`](../../tests/Feature/Demo/DemoSeederGuardTest.php) и сценарий «быстрый вход» ниже.
- Общий пароль всех персонажей — `DEMO_USER_PASSWORD` из `.env`; без него сидер останавливается. TOTP-секрет персонажа с 2FA — `DEMO_TOTP_SECRET`.
- Почта всех персонажей — `имя.фамилия@demo.bz-crm.test`. Письма (приглашения, решения по заявкам, оповещения безопасности) уходят в Mailpit: http://localhost:8126.
- Мир строится один раз на чистой базе; повторный запуск сидера ничего не делает.
- Все данные создаются через доменные действия от имени нужного персонажа, поэтому журнал событий содержит связную историю за последние ~90 дней с правильными акторами.

**Быстрый вход (Д-5).** На странице входа — раскрывающийся блок «Быстрый вход (демо)» со всеми персонажами. Это обычный вход в учётную запись персонажа (не имперсонация), в журнале — отдельная запись «демо-вход».

**Объёмный профиль** для нагрузочных тестов (не входит в демо-мир, запускается вручную): `php artisan db:seed --class=VolumeSeeder` — 5000 людей с учётными записями на домене `load.bz-crm.test`. Каждый следующий модуль добавляет туда свой блок.

## Сценарии демонстрации и тесты
Каждое утверждение «может / не может» подтверждено тестом из `tests/Scenarios` (выполняется на самом демо-мире, в отдельной базе `bz_crm_scenarios`).

### Журнал событий — [`JournalScenariosTest`](../../tests/Scenarios/JournalScenariosTest.php)
- История мира записана с правильными акторами: деактивировал Igor — Natalia (HR), попытку эскалации — Ana, регистрации — гость.
- Запись журнала нельзя изменить или удалить через приложение; откат действия откатывает запись.
- Пароли и client secret в журнал не попадают.
- Natalia (HR) не открывает журнал; Alexandru (СБ) открывает, и сам просмотр записывается.
- Все записи одобрения заявки (решение, назначение ролей) связаны одним `correlation_id`.
- Незарегистрированный тип события отклоняется; у каждого типа есть описания ro/ru/en.

### Вход и регистрация — [`SignInScenariosTest`](../../tests/Scenarios/SignInScenariosTest.php)
- Gheorghe (заявка на рассмотрении) после входа видит только страницу статуса со ссылкой на сайт партии; любая страница панели перенаправляет туда.
- Svetlana видит причину отказа.
- Igor (деактивирован) не может войти; его история на месте.
- Alexandru (2FA) без кода не входит, с кодом — входит.
- Marin входит через Google.
- История входов для СБ: успешные, неуспешные, серия у Pavel, новое устройство у Elena; IP атакующего виден в карточке Pavel.
- Быстрый вход есть в demo-окружениях и отсутствует в `production`; для чужого домена и деактивированного персонажа — отказ.

### Имперсонация (Д-19) — [`ImpersonationScenariosTest`](../../tests/Scenarios/ImpersonationScenariosTest.php)
- Victor Ciobanu входил под Ion Botnaru 12 минут с причиной; в журнале — начало и конец сеанса от имени Victor с пометкой «Имперсонация: от имени Ion Botnaru»; у Иона — уведомление.
- Право имперсонации есть только у суперадминов; под другим суперадмином войти нельзя. Ограничение 30 минут, выход по кнопке, по выходу из системы и при деактивации администратора — [`ImpersonationTest`](../../tests/Feature/Identity/ImpersonationTest.php).
